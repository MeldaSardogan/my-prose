# Security Policy

## Supported versions

| Version | Supported |
|---|---|
| 1.x | Yes |
| Older versions | No |

Only the most recent release line receives security fixes.

## Reporting a vulnerability

Do not report security vulnerabilities in a public GitHub issue,
pull request or discussion.

Please report vulnerabilities through one of these private channels:

1. Open a private GitHub security advisory for this repository.
2. Send an email to `s0577991@htw-berlin.de`.

Include, where possible:

- A description of the vulnerability.
- The affected version.
- Steps to reproduce the problem.
- The possible impact.
- A suggested fix or mitigation.

## Response process

We aim to acknowledge reports within seven days.

After confirming a vulnerability, we will:

1. Investigate the impact.
2. Develop and test a fix.
3. Coordinate disclosure with the reporter.
4. Publish a corrected release.
5. Document the fix in the changelog.

Please allow reasonable time for a fix before publicly disclosing the
vulnerability.

## Third-party dependencies

Security issues in third-party dependencies may also need to be reported
to the maintainers of those dependencies.
